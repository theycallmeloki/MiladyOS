## ISO: dev/production split, dual-console installer, `milady` binary ruling

**Dev entry paths split from production (0308aac).** Every build used to bake
`1350-dev-ssh.chroot` (one operator's SSH pubkey into root) and
`1351-dev-autologin.chroot` (root autologin on serial) — and, because the
installer copies the live rootfs, they landed on installed nodes too. `build.sh`
takes `MILADY_DEV` (default 0); when unset, `build-in-container.sh` deletes both
hooks (`MILADY_DEV=1` keeps them for dev). The installer also strips the serial
autologin drop-in + root authorized_keys from the target, so an install from a
dev ISO is still clean. (PLAN §L2 mentions an "autologin console banner" but
AGENT-FIRST D3 flags blind autologin as a bigger surface — production omits it.)

**The installer was serial-only.** A VGA screendump was 2 colours / 910
non-black pixels: a monitor showed a blank screen, because the installer wrote
to `/dev/console` = the last `console=` (ttyS0). Fix (fa1ee6f, bundled with the
naming docs): `milady-install.service` pins `TTYPath=/dev/tty1`, a new
`milady-install-serial.service` pins `/dev/ttyS0`; both run in the live session
and a `flock` lets only the first to reach the install step proceed. Bootappend
and the installed cmdline gain `console=tty0`; TERM + per-console log follow the
pinned TTY. Verified on 0.0.0.0.704: VGA non-black 0.09% -> 96.75%, serial still
works, full serial-driven install completed.

**`milady` binary ruling (PLAN §Naming; AGENT-FIRST D3/D4).** The old note called
`milady` the "LLM bridge", container-only. It is now the **Go host companion
CLI** (`milady/`: `ask` — replaces the Python mcp-llm-bridge — | `slurp` |
`k3s join` (stub) | `update` | `version`), destined for `/usr/local/bin/milady`
on the host. Four distinct `milady*` objects, none shadowing another: host CLI
(bin) / internal plumbing (`/usr/local/sbin/milady-*`) / OS account (`milady`,
uid 1000) / product (`miladyos`). Ruling recorded. Implementation deferred: the
newest `milady-linux-amd64` release is **0.0.0.0.662** (44 commits behind ISO
.706), so a release fetch would be stale — build from `milady/` in the builder
instead, which needs a Go ≥ 1.27.1 toolchain (trixie's is older; not yet added).

**Clean production ISO:** `0.0.0.0.706`, payload embedded (5.4 GB, reused),

## Style dataset is unusable as-is (Phase 1 finding, decisive)

The 57,733-pair `milady_style` set was generated by the **7B** style teacher
and screened with the 27B judge. The screen had only run 11 pairs (all
`reject`), which looked like a bug. It is not:

- Random 24-pair sample under the **strict** screen prompt: **24/24 reject**.
- Control pairs prove the judge is correct: verbatim copy → `accept,
  style_present=false`; invented content → `reject`. But it also rejects
  ordinary paraphrase that drops a modifier ("most prominent", "Broadway"),
  because the prompt says to reject missing claims.
- Under a **looser core-meaning bar** (paraphrase + dropped incidental
  modifiers allowed; only invented facts / changed subject / flipped negation
  rejected): **3/16 accept (19%)**.

So the judge is literal-but-right; the **teacher invents facts** ("love
spell", "Charlie", "police probaly lub it", "Goliath and Elisa getting
married"). Re-screening cannot fix this — the style data must be
**regenerated by a grounded teacher (the 27B) and judge-verified**. The
existing 57,733 pairs are not safe SFT targets.

Screening throughput once the server is warm: ~0.7 s/pair at concurrency 4
(16 pairs in 10.7 s) — so a full re-screen of 10,606 candidates is ~30–60
min, and a regenerated set is affordable.

- `cidata` volume support: label `cidata` (cloud-init NoCloud) or `milady-join`;

- Package list gains `gum` (Debian trixie `0.14.4-1+b6`; `dialog` kept).

- Docs: `ISO/docs/TEXT-INSTALLER.md` §0 rewritten; `ISO/PLAN.md` D2 + the

**Bugs found and fixed while verifying:**
1. **`</dev/tty` on `gum choose`** — `printf … | gum choose … </dev/tty` redirects
   stdin, *replacing the piped option list*; gum dies with "no options provided"
   and the installer exits silently. Removed the redirects (systemd already makes
   stdin the console tty). Proven in a pty: rc=1 "no options provided" vs rc=124.
2. **`term_width` returned 0 on serial** (a serial console with no negotiated
   winsize reports 0x0) → banner clamped to left. Now tries stty → `$COLUMNS` →
   `tput` → 80.
3. **A 0x0 console starves gum's renderer** — install now `stty rows 24 cols 80`
   when the tty reports no geometry.

**Method note (cost two rebuilds):** the pty harness must pass a *real* typescript
file to `script` (`script -qec … /tmp/t.ts`) — passing `/dev/null` swallows the
output and made gum look broken. Also: `echo 'l' | sudo -S … <<'HEREDOC'` feeds
the heredoc to sudo's stdin, not the password — 9 failed attempts tripped a
lockout that looked like a wrong password.
