### The thinking-budget trap (why mutations arrived empty)
With thinking on, the 27B spends the **entire** 4096-token budget in
`reasoning_content`: `finish_reason=length`, `message.content` = **0 chars** →
`_enforce_fence` clamps the empty mutation back to the original → every
candidate = the template → fitness ties → `best_candidate: null`.
`enable_thinking: false` via `chat_template_kwargs` → 283 tokens, 5.5 s,
951 chars of real YAML (was 0 chars / 66 s). Verified 12x faster too.

### Selection bugs fixed (made `evolve_template` return null)
1. Falsy-fitness: `if candidate.fitness and ...` treats a real **0.0** as
   missing — `_get_best_fitness`, both loops of `_get_best_candidate`, and the
   sort keys of `_migrate`/`_evolve_populations`/`_tournament_select`
   (there, `c.fitness or -inf` ranked a valid 0.0 candidate *below* an invalid
   -1.0 one). Symptom before: `best_fitness: -Infinity`, `best_candidate: null`.
2. Archive aliasing: `_update_archive` stored references; `_evolve_populations`
   resets an elite's `fitness = None` for re-evaluation, erasing the score of
   every archived candidate → final `_get_best_candidate` returned None. Now
   stores `replace(candidate)` snapshots.

### Open findings (reported, NOT fixed)
- **Reward hack, live:** `goal=reliability` selected a candidate with fitness
  **0.466** that had **deleted the build and test steps** — `error_handling_score
  = min(1, (when+2*failure)/step_count)` rewards fewer steps. The fence keeps the
  skeleton but not intra-payload step structure, and `_check_syntax` only
  requires *a* steps mapping. Artifact:
  `evolved_templates/example-build_evolved_reliability_20260920_062919.yml`.
- **`goal=speed` has no static signal:** weights `duration_score 1.0` +
  `success_rate 0.3` are execution-only (absent unless
  `evaluator.live_execution: true`); only `parallelism_score 0.5` is static, so
  candidates tie at 0.0 and the strict `>` keeps the incumbent — a sane mutation
  (`npm install` → `npm install --ignore-scripts`) is never adopted.
- **Redis URL never expands:** `storage.redis.url` is
  `"${REDIS_URL:-redis://localhost:6379}"` and `os.path.expandvars` has no
  `:-default` syntax → literal string → `redis.from_url` fails
  ("Redis URL must specify one of the following schemes") → engine state
  persistence silently off.
- **`/app/templates` is empty in the image** (created empty on purpose for the
  app user), so `evolve_template` says "Template not found" on a fresh container.
  Seeded for this run via `docker cp templates/. miladyos:/app/templates/`.
  One-line fix if wanted: `COPY templates/ /app/templates/` (needs a rebuild).
